# 數學模型驗證與 PAR Sheet 指引

本指引涵蓋數學模型的**驗證**（證明模型正確）與**文件化**（讓實驗室與監管機關可獨立複核）。模型的**設計**方法見 `math-model.md`。

---

## 0. 為什麼驗證是獨立的工作階段

實驗室不接受「我們算過了」。認證要求的是**可獨立重現的證明**：實驗室會拿到 PAR sheet 與模擬工具，自行跑一次，比對結果是否與宣稱值一致。

因此驗證階段的產出不是一個 RTP 數字，而是三件事必須互相吻合：

1. **理論值**——由賠率表與捲軸帶解析計算（closed-form 或完全列舉）
2. **模擬值**——由實際遊戲程式碼跑大量旋轉統計
3. **宣稱值**——寫在 PAR sheet 與遊戲資訊面板上的數字

三者不一致就是缺陷。最常見的情況是理論值與模擬值有系統性落差，原因幾乎都是實作與模型脫節（見 §4 常見錯誤），而不是隨機誤差。

---

## 1. 理論 RTP 計算

### 1.1 完全列舉 vs 解析計算

**完全列舉（exhaustive cycle）**適用於捲軸帶組合數可窮盡的情況。5 軸各 32 格的組合數為 32⁵ = 33,554,432，現代硬體可在數分鐘內完全列舉，得到**精確**理論值而非估計值。

若使用虛擬捲軸加權映射（見 `math-model.md` §2.1），列舉的是虛擬位置組合而非實體符號組合。這是必須注意的差別：以實體捲軸列舉會得到錯誤的機率分布。

**解析計算**適用於組合爆炸的情況（多軸、長捲軸帶、多層獎勵）。此時把 RTP 拆解為各元件貢獻之和：

```
RTP_total = RTP_base + RTP_freespin + RTP_bonus + RTP_jackpot
```

每個元件獨立驗算，最後加總。分項驗算的好處是實驗室可逐項複核，也讓 jackpot 移除（例如德國市場）時能清楚看出需要重新分配多少。

### 1.2 精確度要求

以**有理數或高精度小數**進行 RTP 計算，不要用 32 位元浮點累加。理由：完全列舉會累加數千萬項，float32 的累加誤差可達第三位小數，足以讓宣稱值與實驗室複核值不一致。

實務建議：中間計算以整數表示「總回報單位」（以最小投注單位為分母），最後一步才轉為百分比。這樣理論值可表示為精確分數，實驗室複核時能得到完全相同的數字。

## 2. Monte Carlo 模擬驗證

### 2.1 樣本量該取多少：先算，不要猜

⚠️ 「跑一百萬次旋轉」是產業口耳相傳的數字，**未見於 GLI-11 v3.0、GLI-19 v3.0 或已查證的州級技術標準**（見 `jurisdiction-matrix.md` §5.5）。GLI 對軟體 RNG 的要求是定性的：「測試資料量須足以高頻率偵測出對適用 RNG 測試準則的顯著偏離」。

因此樣本量應由**目標精度**反推，而非沿用慣例。

單次旋轉回報的標準差 σ 決定所需樣本量。RTP 估計值的標準誤為：

```
SE = σ / √n
```

要讓 RTP 估計的 95% 信賴區間半寬不超過 ε：

```
1.96 × σ / √n ≤ ε
⟹ n ≥ (1.96 × σ / ε)²
```

**這裡的關鍵是 σ 隨波動性劇烈變化**，所以高波動遊戲需要的樣本量遠高於低波動遊戲：

| 波動性等級 | 單次回報標準差 σ（典型範圍，以投注額為單位） | 達到 ±0.1% RTP 精度所需 n（量級） |
|-----------|------|------|
| 低（Low） | 3–5 | 約 10⁷ |
| 中（Medium） | 6–10 | 約 10⁸ |
| 高（High） | 12–25 | 10⁸–10⁹ |
| 極高（Very High） | 30+ | 10⁹ 以上 |

**σ 必須由實際模型量測，不可套用上表。** 上表僅用於估算計算資源需求的量級。正確流程是：先跑一次較小規模模擬（例如 10⁶ 次）估出 σ，再用上式計算達到目標精度所需的 n，然後跑正式模擬。

**含大獎的模型要特別小心**：若最高獎項為 50,000 倍投注且觸發機率為 10⁻⁸，則 10⁸ 次模擬中該獎項的出現次數期望值僅為 1。此時模擬 RTP 會因為「這一次有沒有中」而跳動數個百分點，模擬值完全無法用於驗證。

**正確做法是分離處理**：極低頻高額獎項以解析法計算其 RTP 貢獻，模擬只驗證其餘部分，再將兩者相加。試圖用暴力模擬涵蓋長尾是常見的資源浪費且結論不可靠。

### 2.2 理論值與模擬值的一致性判定

不要用「差異小於 0.1% 就算通過」這種固定門檻，因為它沒有考慮樣本量與波動性。正確的判定是**模擬值是否落在理論值的信賴區間內**：

```
|RTP_sim − RTP_theory| ≤ 1.96 × σ_sim / √n     (95% 信心)
```

若超出區間，這是**系統性偏差的證據**，不是運氣不好。應依 §4 逐項排查實作與模型的脫節。

同時驗證的不只是 RTP，還有：

| 指標 | 驗證方式 |
|------|---------|
| RTP | 理論值 vs 模擬值，信賴區間判定 |
| 命中頻率（Hit Frequency） | 理論值 vs 模擬值 |
| 各獎項的個別命中率 | 逐獎項比對，可定位到特定賠付組合的錯誤 |
| 各元件 RTP 貢獻 | base／free spin／bonus／jackpot 分項比對 |
| 標準差與波動性指標 | 模擬量測，寫入 PAR sheet |
| 最大單局回報 | 模擬觀測最大值 vs 理論最大值 |
| 獎勵功能觸發率 | 理論值 vs 模擬值 |

**逐獎項比對是最有價值的除錯工具。** 總 RTP 相符但某個獎項的命中率偏差，通常代表該賠付組合的判定邏輯有錯（例如 wild 替代規則），而總值因其他獎項的反向偏差而被掩蓋。

### 2.3 模擬必須用產品程式碼

模擬若使用另寫的模型腳本，證明的是模型正確，而非**產品**正確。實驗室要驗證的是實際會上線的邏輯。

因此模擬應：

- 呼叫與生產環境相同的規則評估與賠付計算程式碼路徑
- 僅替換 RNG 為可設定種子的版本（用於可重現性），其餘不變
- 使用與生產環境相同的設定檔（賠率表、捲軸帶 JSON）

### 2.4 可重現性

實驗室會要求重現特定結果。因此需具備：

- **可設定種子的模擬模式**：給定種子必產生相同序列（僅用於測試，生產環境必須使用 CSPRNG，見 `rng-game-logic.md` §1）
- **確定性重播**：給定一組 RNG 輸出值，能重現完整的遊戲結果與賠付計算過程
- **中間值輸出**：能匯出每局的 RNG 原始值、映射後的捲軸位置、命中的賠付線與各線賠付額

第三項在實驗室爭議時是決定性的。若只能輸出最終賠付額，無法證明中間計算正確。

## 3. PAR Sheet（Probability and Accounting Report）

PAR sheet 是數學模型的正式文件，也是實驗室與監管機關審查的核心文件。結構化範本見 `templates/certification/par-sheet.json`。

### 3.1 必要章節

| 章節 | 內容 | 為何需要 |
|------|------|---------|
| 1. 遊戲識別 | 遊戲名稱、版本、建置雜湊值、數學模型版本 | 綁定文件與特定建置 |
| 2. 遊戲組態 | 軸數、列數、賠付線數／方式、投注結構、幣別 | 定義計算基礎 |
| 3. 符號清單 | 所有符號、類型（普通／wild／scatter／bonus） | 賠付表的前提 |
| 4. 捲軸帶 | 每軸的完整符號序列；虛擬映射時同時列出實體與虛擬 | 可獨立重算機率 |
| 5. 賠付表 | 每個符號組合的倍數 | 可獨立重算 RTP |
| 6. 賠付線定義 | 每條線的位置座標，或 ways/cluster 規則 | 命中判定的前提 |
| 7. 規則說明 | wild 替代、scatter 觸發、multiplier 套用、評估順序 | 消除歧義 |
| 8. RTP 分解 | 各元件貢獻與總計，理論值 | 核心宣稱值 |
| 9. 命中頻率 | 總命中率與各獎項命中率 | 交叉驗證 |
| 10. 波動性指標 | 標準差、波動性等級、最大回報倍數 | 玩家揭露與風險評估 |
| 11. 模擬結果 | 樣本量、模擬 RTP、信賴區間、與理論值比對 | 獨立證據 |
| 12. 獎勵功能明細 | 每個功能的觸發機率、期望值、RTP 貢獻 | 分項複核 |
| 13. Jackpot 明細（若有） | 貢獻率、種子值、命中機率、期望回報 | GLI-12 相關 |
| 14. 投注配置矩陣 | 每個可用投注額下的 RTP | **關鍵**，見 §3.2 |
| 15. 變更記錄 | 相對前一版的變更與影響 | 變更管理 |

### 3.2 投注配置矩陣：最常被忽略的一節

GLI-11 與 GLI-19 都要求最低 RTP **在所有投注配置下**皆須滿足；賓州技術標準 §461b.6 更明確要求以最低單次投注計算不得低於 85%、以最高合格投注計算不得達到或超過 100%。

這意味著**不能只提供單一 RTP 數字**。若遊戲的 RTP 隨投注額變化（常見於 ante bet、bonus buy、投注額解鎖額外賠付線的設計），必須列出每個投注級距的 RTP。

**這是設計層的陷阱**：常見的「投注越高、RTP 越高」設計會導致最低投注額的 RTP 落到門檻以下。若目標市場有 RTP 下限，設計時就必須確保**最低投注配置**也達標，而非只看標稱 RTP。

技能影響型遊戲另有要求：GLI-19 §4.7.1 規定須以**最佳玩法**計算並滿足最低 RTP；密西根 R 432.633b(1) 要求在技能影響 RTP 時同時計算**最高與最低技能水準**下的 RTP。

### 3.3 揭露一致性

PAR sheet 的 RTP 必須與遊戲內揭露一致。多個市場強制揭露：

- 英國：RTS 3C 要求於玩家投注前揭露 RTP 或中獎機率；RTS 9 要求揭露 jackpot RTP
- 德國：§22a(3) 要求在下注處顯示每 €1 投注的平均派彩率**以及中最高獎金的機率**
- 安大略：Standard 4.07 要求揭露包含最高獎金在內的限制
- 康乃迪克：無法滿足派彩率要求的遊戲類型須向玩家顯示最低 RTP

德國的要求特別注意：它要求的不只是 RTP，還包括**中最高獎金的機率**。這個數字必須在 PAR sheet 中明確計算並可追溯。

## 4. 常見驗證失敗原因

依實務發生頻率排序。當理論值與模擬值不符時，依序排查。

### 4.1 虛擬捲軸映射錯誤

以實體捲軸長度計算機率，而實作使用虛擬加權映射（或反之）。這會造成整體 RTP 系統性偏差。

排查方式：統計模擬中**每個實體符號在每軸的實際出現頻率**，與虛擬映射表推導的期望頻率比對。任一軸不符即定位到問題。

### 4.2 加權選擇的邊界偏差

從 CSPRNG 位元組映射到 `[0, n)` 範圍時使用取模運算（`value % n`），在 n 不是 2 的冪次時會產生偏差——較小的餘數出現機率略高。

正確做法是**拒絕取樣（rejection sampling）**：丟棄落在最大整數倍以上的值後重取。GLI-11 §3.2.3 明確允許丟棄 RNG 值以消除偏差，且會透過原始碼審查檢查縮放與映射演算法的無偏性。

這個偏差在低樣本量下不易察覺，但實驗室的 chi-square 與分布檢定會抓到。

### 4.3 Wild 替代的重複計算

同一條賠付線上，wild 同時作為替代符號與自身賠付符號被計入兩次，或取「最高賠付」時的比較邏輯有誤。

排查方式：逐獎項命中率比對（見 §2.2）。含 wild 的組合命中率偏高即為此問題。

### 4.4 Scatter 賠付被計入賠付線

Scatter 依定義是**不分位置**的整盤判定，若誤按賠付線邏輯逐線計算，會導致多線遊戲的 scatter 賠付被放大數倍。

### 4.5 Multiplier 套用順序

Multiplier 應在賠付線加總前或後套用，取決於規則定義。順序錯誤在單一 multiplier 時可能無差異，但在多個 multiplier 疊加或 multiplier 僅適用部分賠付時會產生偏差。規則說明（PAR sheet §7）必須明確定義評估順序，實作與理論計算須採相同順序。

### 4.6 Free Spin 期間的規則差異未納入模型

Free spin 常使用不同捲軸帶、不同 multiplier 或可再觸發（retrigger）。理論計算若沿用基礎遊戲參數，或未計入 retrigger 的無窮級數收斂，會低估 free spin 的 RTP 貢獻。

Retrigger 的期望值計算：若每次 free spin 有機率 p 再觸發 k 次，則期望總次數為幾何級數 `n / (1 − p·k)`，需確認 `p·k < 1` 否則模型發散——這本身就是設計錯誤的訊號。

### 4.7 浮點累加誤差

見 §1.2。以整數單位累加，最後才轉百分比。

### 4.8 模擬使用了非產品程式碼

見 §2.3。模型腳本與產品實作分歧是最難察覺的一類，因為兩邊各自「正確」。

## 5. 波動性與玩家體驗指標

除 RTP 外，PAR sheet 應包含以下指標，因為它們是監管機關評估遊戲風險特徵的依據，也是揭露要求的來源。

| 指標 | 定義 | 用途 |
|------|------|------|
| 標準差（σ） | 單次旋轉回報的標準差 | 波動性的量化基礎 |
| 波動性指數 | 依 σ 分級（見 `math-model.md` §4.1） | 玩家揭露與產品定位 |
| 命中頻率 | 產生任何回報的旋轉比例 | 玩家體驗 |
| **有效命中頻率** | 回報**大於**投注額的旋轉比例 | 見下方說明 |
| 最大回報倍數 | 單局理論最高回報 / 投注額 | 揭露要求（英國、安大略、德國） |
| 中最高獎金的機率 | 觸發最高獎項的機率 | **德國 §22a(3) 強制揭露** |
| 破產機率 | 給定起始資金下的破產機率曲線 | 風險評估 |

**有效命中頻率值得單獨計算**，因為英國 RTS 14F 與安大略 Standard 2.20 都**禁止慶祝回報 ≤ 投注額的結果**。這代表遊戲必須能區分「有回報」與「有淨獲利」，而傳統命中頻率把 0.5 倍投注的回報也算作命中。若產品的視聽回饋以命中頻率驅動，在這兩個市場會直接違規。

## 6. 送測前的自我驗證清單

送交實驗室前應完成：

- [ ] 理論 RTP 以完全列舉或解析法計算，使用高精度算術
- [ ] 樣本量由目標精度與實測 σ 反推，非沿用慣例數字
- [ ] 極低頻高額獎項以解析法處理，未依賴暴力模擬
- [ ] 模擬使用產品程式碼路徑與生產設定檔
- [ ] 模擬值落在理論值的 95% 信賴區間內
- [ ] 逐獎項命中率比對通過
- [ ] 各元件 RTP 貢獻分項比對通過
- [ ] **所有投注配置**的 RTP 皆已計算並滿足目標市場下限
- [ ] 最低投注配置的 RTP 亦達標（非僅標稱值）
- [ ] 技能影響型遊戲已計算最佳玩法與最高／最低技能水準的 RTP
- [ ] 可設定種子的重現模式可用，中間值可匯出
- [ ] 有效命中頻率已計算（區分回報 vs 淨獲利）
- [ ] 中最高獎金的機率已計算（德國市場必需）
- [ ] PAR sheet 十五個章節齊備
- [ ] PAR sheet 的 RTP 與遊戲內揭露文案一致
- [ ] 建置雜湊值已記錄並與 PAR sheet 綁定
- [ ] 若移除 jackpot 供特定市場使用，該版本的 RTP 已重新配置與驗算
