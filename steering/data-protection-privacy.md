# 資料保護與隱私合規指引

老虎機系統處理的資料同時受**博彩監管**與**資料保護法**約束，而這兩套要求會**互相衝突**：博彩監管要求長期保存稽核紀錄，資料保護法要求資料最小化與限期刪除。本指引處理這個衝突。

---

## 1. 兩套要求的衝突與解法

### 1.1 衝突的具體樣貌

| 博彩監管要求 | 資料保護要求 | 衝突點 |
|-------------|-------------|--------|
| 稽核日誌不可篡改、長期保存（瑞典 5 年、西維吉尼亞 5 年＋開發文件 7 年） | 資料保存期限應為達成目的之必要最短期間 | 保存期 |
| 行為監控以識別問題博彩（瑞典盡職照護義務、荷蘭淨損失門檻） | 特殊類別資料與自動化決策限制 | 處理範圍 |
| 玩家身分與交易紀錄須可供監管機關存取 | 資料主體有存取、更正、刪除權 | 刪除權 vs 保存義務 |
| 德國 §6h(5)：並行遊戲資料**必須**於等待期後刪除 | 一致 | （罕見的一致案例） |

### 1.2 解法：資料分類與差異化生命週期

**不要採用單一保存策略。** 正確做法是把資料分類，各自定義法律依據、保存期與刪除規則：

| 資料類別 | 法律依據（GDPR） | 保存期 | 刪除權適用 |
|---------|-----------------|-------|-----------|
| 遊戲局結果與賠付 | 法律義務（Art. 6(1)(c)） | 依市場法定期間 | ❌ 保存期內不適用 |
| 帳戶與交易紀錄 | 法律義務 | 依市場法定期間 | ❌ 保存期內不適用 |
| 身分與年齡驗證紀錄 | 法律義務 | 依市場法定期間 | ❌ |
| AML 監控紀錄 | 法律義務 | 依 AML 法規（通常長於博彩法） | ❌ |
| 自我排除紀錄 | 法律義務 | 排除期間＋後續期間 | ❌ |
| 並行遊戲控管資料（德國） | 法律義務，**且法定強制刪除** | 等待期屆滿即刪除 | ✅ 強制 |
| 行銷偏好與同意紀錄 | 同意（Art. 6(1)(a)） | 至撤回同意 | ✅ |
| 行為分析／個人化 | 同意或正當利益 | 明確定義 | ✅ |
| 客服往來紀錄 | 契約履行或正當利益 | 明確定義 | ⚠️ 部分 |

**關鍵訊息**：玩家行使刪除權時，**不能刪除受法律義務保存的資料**，但**必須**刪除同意基礎的資料。若系統無法區分，就無法同時滿足兩套法規。這是架構問題，不是流程問題。

⚠️ 德國 §6h(5) 要求並行遊戲資料於等待期後刪除**並禁止用於其他目的**。這與「稽核資料一律長期保存」的預設做法直接衝突。若系統把所有事件寫入同一份 append-only 日誌，就無法執行這項強制刪除。

## 2. GDPR 要點（適用歐盟／英國市場）

### 2.1 法律依據的選擇

博彩業常見錯誤是把所有處理都建立在「同意」上。這在博彩業行不通，因為：

- 年齡驗證、KYC、AML、自我排除都是**法律義務**，不需也不應依賴同意
- 若以同意為依據，玩家撤回同意時營運商將無法履行法定義務
- 同意必須是自由給予的；若不同意就不能遊玩，該同意在法律上無效

正確做法：法定義務相關處理以 Art. 6(1)(c) 法律義務為依據；行銷與個人化才使用同意。

### 2.2 特殊類別資料的風險

問題博彩監控可能涉及**健康資料**（Art. 9 特殊類別）。瑞典 Spellag 14:1 要求持續行為監控與書面行動計畫；荷蘭要求淨損失門檻觸發強制接觸。

這類處理需要 Art. 9 的例外依據，且應：

- 進行資料保護影響評估（DPIA）
- 限制存取範圍
- 記錄處理目的與依據
- 特別注意若以自動化方式做出對玩家有重大影響的決定（如強制限額、帳戶關閉），可能觸及 Art. 22 自動化決策限制

⚠️ 德國 €5 投注級距要求「前 90 天無問題博彩指標」（MEDIUM）——這是**以健康相關推論驅動產品參數**。若該制度確認生效，其資料保護分析應由律師處理，不應由技術團隊自行判斷。

### 2.3 資料主體權利的實務處理

| 權利 | 博彩業的限制 |
|------|-------------|
| 存取權 | 通常可行；但不得洩漏 AML 可疑活動報告的存在（多數司法管轄區禁止 tipping off） |
| 更正權 | 身分資料更正需重新驗證 |
| 刪除權 | 受法律義務保存的資料不適用 |
| 限制處理權 | 不得妨礙法定義務履行 |
| 可攜權 | 僅適用同意或契約基礎且自動化處理的資料 |
| 反對權 | 行銷可反對；法定義務處理不可 |

**AML 相關的 tipping off 禁令**值得特別注意：玩家行使存取權時，不得揭露其為可疑活動調查對象。這需要在存取權處理流程中設計排除機制。

## 3. 資料落地與跨境傳輸

### 3.1 博彩法的資料落地要求

見 `jurisdiction-matrix.md` §4.1 與 `platform-systems-compliance.md` §8。已確認的硬性要求：瑞典（遊戲系統須位於瑞典境內）、西維吉尼亞（資料倉儲須位於州內）。

**注意這與 GDPR 的跨境傳輸規則是不同的兩套要求。** 瑞典的要求不是資料保護法要求，而是博彩監管的**主管機關存取**要求——即使資料留在歐盟境內（GDPR 無傳輸問題），仍可能違反瑞典博彩法。

### 3.2 跨境傳輸的合規路徑

歐盟／英國資料移出時需要傳輸機制：適足性認定、標準契約條款（SCC）、或其他 Art. 46 機制。實務要點：

- 雲端服務的區域選擇需與資料落地要求一致
- 支援團隊的遠端存取構成傳輸
- 監管機關要求的資料報送若跨境，需確認傳輸依據
- 第三方服務（KYC 供應商、支付、分析、反詐欺）各自需評估

### 3.3 常見架構錯誤

| 錯誤 | 問題 |
|------|------|
| 單一全球資料庫 | 無法滿足瑞典、西維吉尼亞的落地要求 |
| 日誌集中匯總到單一區域 | 稽核日誌可能構成跨境傳輸 |
| 分析平台位於第三國 | 行為資料傳輸需依據 |
| 備份跨區複製未評估 | 備份也是傳輸 |
| 支援人員全球存取 | 存取即傳輸 |

## 4. 供應商與處理者管理

### 4.1 角色判定

| 情境 | 角色 |
|------|------|
| 營運商決定處理目的 | 控制者（Controller） |
| B2B 遊戲供應商依營運商指示處理玩家資料 | 通常為處理者（Processor） |
| B2B 供應商為自身目的使用資料（如產品分析） | 該處理部分為控制者 |
| 自研自營 | 控制者 |

⚠️ B2B 供應商常見錯誤：以處理者身分收取玩家資料，但用於自身的產品分析或模型訓練。這使供應商在該處理上成為控制者，而其未取得法律依據。合約與實際處理必須一致。

### 4.2 必要文件

- 資料處理協議（DPA），明確處理目的、範圍、期間、安全措施、次處理者
- 次處理者清單與變更通知機制
- 資料流圖（哪些資料、從哪到哪、依據為何）
- 保存與刪除排程
- 資料外洩通報流程與時限（GDPR 72 小時）

## 5. 資料外洩處理

博彩業的資料外洩具備兩重通報義務：

1. **資料保護機關**：GDPR Art. 33，72 小時內（若可能對權利自由造成風險）
2. **博彩監管機關**：依牌照條件，時限通常更短

若外洩涉及自我排除名單或問題博彩監控資料，敏感度極高——這些資料能揭示個人的成癮狀態。應在事故分級中視為最高等級（見 `incident-malfunction-handling.md` §2）。

證據保全與事故處理程序見 `incident-malfunction-handling.md` §3。

## 6. 資安控制與標準對應

| 標準 | 用途 | 現況 |
|------|------|------|
| GLI-GSF-1 Gaming Information Security Controls Audit | 遊戲業資安控制稽核 | v1.1 |
| GLI-GSF-2 Gaming Technical Security Assessment | 技術安全評估 | v1.0 |
| GLI-GSF-3 GIS Vendors Audit | 供應商資安稽核 | v1.0 |
| GLI-GSF-5 GIS Online Audit | 線上營運資安稽核 | v1.0 |
| 丹麥 SCP.03 | ISMS 要求 | 認證方案一部分 |
| 丹麥 SCP.04／SCP.05 | 滲透測試／弱點掃描 | 認證方案一部分 |
| ISO/IEC 27001 | 資訊安全管理系統 | GLI 亦提供此認證服務 |
| WLA-SCS:2024 | 彩券與運動賭博安全控制標準，基於 ISO/IEC 27000 系列 | MEDIUM |
| 英國 | 年度獨立安全稽核（牌照要求） | HIGH |

**丹麥 SCP.03／04／05** 是公開且結構清晰的資安要求文件，適合作為內部資安基準的骨架，即使不進丹麥市場。

## 7. 檢查清單

- [ ] 資料已分類，各類別有明確的法律依據
- [ ] 法定義務處理**未**建立在同意之上
- [ ] 保存期依類別分別定義，對應各市場法定期間
- [ ] 刪除機制能區分「受法律義務保存」與「可刪除」資料
- [ ] 德國並行遊戲資料的強制刪除可執行（若進入德國市場）
- [ ] 問題博彩監控的 Art. 9 依據已確認，DPIA 已完成
- [ ] 自動化決策若對玩家有重大影響，Art. 22 分析已完成
- [ ] 資料主體權利處理流程含 AML tipping off 排除機制
- [ ] 資料落地要求已反映於部署拓撲（博彩法要求，與 GDPR 分開評估）
- [ ] 跨境傳輸機制已建立，含備份、日誌匯總、支援存取、第三方服務
- [ ] 控制者／處理者角色與實際處理一致
- [ ] B2B 供應商未在處理者身分下為自身目的使用資料
- [ ] DPA、次處理者清單、資料流圖、保存刪除排程齊備
- [ ] 資料外洩雙軌通報流程已建立（資料保護機關＋博彩監管機關）
- [ ] 自我排除與問題博彩資料的外洩已列為最高事故等級
- [ ] 資安控制對應至目標市場要求的標準
